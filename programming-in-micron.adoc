== The Language and Its Reasons

This part explains why the Micron programming language exists, what using it looks like,
and it lays down the vocabulary the rest of the book depends on.
<<ch01>> makes the case for another systems language, positioning Micron against C, the Pascal lineage and Go.
<<ch02>> takes a tour through complete programs and the toolchain to prepare the reader for the details.
<<ch03>> introduces the notation and lays the ground every later chapter builds on: the types, the literals, and the strict
separation of signed and unsigned integers that distinguishes Micron most visibly from its ancestors.
<<ch04>> addresses readers arriving from C, Pascal or Go directly, with the reasoning behind the differences.

== The Language in Depth

This part covers the language feature by feature, roughly in the order of the
language levels introduced in <<ch02>>: from the structure every program has, modules, 
procedures and statements, through structured types, abstraction and
dynamic memory, to objects, generics, compile-time programming, the low-level
constructs and the C boundary, then the library modules that accompany
the compiler, ending with error handling.
Each chapter explains what problem a feature solves, at which level it becomes available,
and where Micron deliberately differs from Oberon, Pascal, C or Go.
Every listing is a compilable program or an excerpt of one; the sources accompany the book.

== Systems Programming — The Micron System

In this chapter, the Micron System is presented,
which is a port of Niklaus Wirth and Jürg Gutknecht's Project Oberon (edition 2013) <<R2>> to Micron,
an operating system with a file system, a garbage collector, a display,
an editor and a graphics application, in 27 modules, on an emulated machine,
with no C underneath.
An operating system is the natural showcase for this book because it exercises everything <<part2>> introduced, 
at every level of the language:
memory-mapped devices and register access at the bottom,
procedure variables and Wirth's message-based object style in the viewers,
the garbage collector both implemented (in the Kernel) and used (above it).
Where Oberon needed the SYSTEM pseudo-module and a boot linker,
Micron has all in the language, and the result is one linked image.

The chapters follow the system bottom-up, from the machine to the applications.
Wirth and Gutknecht's book remains the reference for the design;
the following chapters presume no prior reading of it, but they focus on what Micron
makes different and quote the original only where the contrast teaches something.
None of it is specific to operating systems: the same techniques serve anyone writing firmware,
drivers, runtimes or any other program that owns its machine.
